## Executive Summary

Kesho is building a digital savings app for informal-sector workers in Kenya, allowing groups to manage their chamas digitally. The app will track contributions, predict defaults, and provide a reputation system. The target users are market traders, boda riders, and others who earn daily in cash and have limited banking relationships.

**Business objectives**

- Provide a reliable and secure digital platform for informal savings groups
- Reduce disputes and increase trust among group members
- Comply with relevant regulatory requirements

## Scope

**In scope**

- Development of a mobile app for Android devices
- Integration with M-Pesa for money transactions
- Contribution tracking and payout management
- Group admin features for monitoring and chasing late payments
- Reputation system for members
- Support for English and Swahili languages

**Explicitly out of scope**

- Banking or financial services beyond digital chama management
- Hardware or infrastructure provision for users
- Comprehensive user training or support programs

## Recommended Tech Stack

| Layer | Choice | Why | Runner-up | Why not |
|---|---|---|---|---|
| Frontend | **React Native** | Cross-platform compatibility, large community support, and ease of development for Android devices, which is the primary target for this project | Flutter | While Flutter is a strong alternative, React Native's larger community and more extensive library support make it a better fit for this project's medium complexity and the need for rapid development |
| Backend | **Node.js with Express.js** | Well-established framework for building scalable and secure server-side applications, with extensive support for integrating with third-party services like M-Pesa | Django | Django, while robust, has a steeper learning curve and is more opinionated, which could slow down development for a small team |
| Database | **PostgreSQL** | Reliable, scalable, and feature-rich open-source database that supports complex queries and has strong support for transactions, necessary for managing financial data | MySQL | PostgreSQL offers better support for advanced data types and querying capabilities, making it more suitable for the financial tracking and prediction aspects of the app |
| Hosting | **AWS** | Comprehensive set of services that can support the application's needs, from compute and storage to database and security, with a strong presence in Africa for low latency | Google Cloud Platform (GCP) | AWS has a more established presence in Africa and offers more competitive pricing for small to medium-sized projects, making it a better fit for this startup |
| Auth | **OAuth 2.0 with Okta** | Secure, scalable, and widely adopted authorization framework that can handle the app's authentication needs, including support for M-Pesa integration | Auth0 | Okta offers more comprehensive features for identity and access management, particularly for enterprise and financial applications, making it a better choice for compliance and security |
| CI/CD | **Jenkins** | Mature, open-source automation server that supports a wide range of development lifecycles, including build, test, and deployment, with a large community for support | GitLab CI/CD | Jenkins offers more flexibility and customization options, which are beneficial for integrating with the diverse set of tools and services used in this project |
| Monitoring | **Prometheus and Grafana** | Prometheus provides robust monitoring and alerting capabilities, while Grafana offers flexible and customizable dashboards for visualizing application performance and health | New Relic | The combination of Prometheus and Grafana offers more cost-effective and customizable monitoring solutions, which are crucial for a startup's budget and specific needs |
| M-Pesa Integration | **Daraja API by Safaricom** | Official API provided by Safaricom for integrating M-Pesa services into applications, ensuring compliance and reliability for financial transactions | Third-party M-Pesa SDKs | Using the official Daraja API ensures direct support from Safaricom and compliance with regulatory requirements, reducing the risk of integration issues or service disruptions |

**Architecture**

- The React Native frontend will communicate with the Node.js backend via RESTful APIs, secured with OAuth 2.0 and Okta for authentication.
- The backend will utilize PostgreSQL for database operations, ensuring data integrity and scalability.
- M-Pesa integration will be handled through the Daraja API, facilitating secure and compliant financial transactions.
- Monitoring will be achieved through Prometheus and Grafana, providing real-time insights into application performance and health.

**Scaling considerations**

- As usage grows, the database (PostgreSQL) will likely be the first component to require scaling, which can be addressed by upgrading to more powerful instances or implementing sharding.
- The Node.js backend may also require additional instances or more efficient routing to handle increased traffic, which can be managed through AWS auto-scaling features.
- To mitigate the risk of non-compliance with regulatory requirements, regular audits and compliance checks will be necessary, potentially involving third-party services for support.
