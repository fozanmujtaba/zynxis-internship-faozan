# Week 4 — RAG for Agents

**Task:** Build a Retrieval-Augmented Generation pipeline to search a local PDF knowledge base.

## What This Demonstrates

| Concept | How it's shown |
|---|---|
| PDF ingestion | `ingest.py` extracts text per-page with `pypdf`, chunks it, and embeds it into ChromaDB |
| Retrieval | `rag.py` embeds the query and pulls the top-k most similar chunks, labeled by source file + page |
| Grounded generation | The LLM is instructed to answer only from retrieved context and to cite its source |
| Accuracy measurement | `eval.py` runs a 10-question test set and scores retrieval accuracy and generation accuracy independently |

## Pipeline

```
PDFs (./docs) --ingest.py--> chunks --embed--> ChromaDB (./chroma_store)

User query --embed--> ChromaDB similarity search --> top-k chunks
    --> [system prompt + context] --> Groq LLM --> cited answer
```

## Knowledge base

Reuses this repo's own Week 1 and Week 3 deliverable PDFs (`docs/`) — since
their content is already known, every test question's ground truth is
independently checkable against the source PDF.

## Setup

```bash
cd Week_4
python -m venv venv
source venv/bin/activate     # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

The `.env` file already contains `GROQ_API_KEY` (same key as Weeks 1-3).

## Run

```bash
# 1. Ingest the PDFs into ChromaDB (run once, or after adding new PDFs to ./docs)
python ingest.py            # add --reset to wipe the collection first

# 2. Query the pipeline
python rag.py                          # demo queries + interactive REPL
python rag.py -q "Which animal does Bob own in the Week 1 Zebra puzzle?"

# 3. Run the accuracy evaluation
python eval.py                         # prints per-question + summary results
python eval.py --json eval_results.json   # also dumps raw results as JSON
```

## Results

**Retrieval accuracy: 10/10 (100%)** · **Generation accuracy: 10/10 (100%)**

See [accuracy_report.pdf](accuracy_report.pdf) / [accuracy_report.md](accuracy_report.md)
for methodology, the full per-question breakdown, and honest limitations of
this benchmark (small n, keyword-based scoring, a deliberately small/known
corpus). Raw transcripts are in `eval_results.json`.
